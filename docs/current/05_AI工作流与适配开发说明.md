# AI 工作流与适配开发说明

## 1. 三个业务操作

```text
extract_requirements(blocks, context, scope) -> AIRequirementsResponse
extract_material_fields(blocks, material_types, field_definitions) -> AIMaterialsResponse
evaluate_requirement(requirement, materials, rule_checks, coverage) -> AICheckResponse
```

类型见 contracts/domain.schema.json。所有输入已由业务后端提供来源编号；平台不需要读取原文件路径。

返回的是候选和建议，后端校验后分配正式 ID 并保存。provider、is_simulated、模型/提示词版本、平台运行 ID 由适配代码记录，不相信模型自报。

## 2. 适配器

| 适配器 | 行为 |
|---|---|
| MockWorkflowAdapter | 显式开发模式；基于测试输入生成可复现输出，标 is_simulated=true；非匹配输入可返回未知，不伪造证据 |
| HaierWorkflowAdapter | 只在获得真实 API 示例后实现鉴权、字段和响应映射 |
| InternalModelAdapter | 使用已有内部模型协议及相同提示词/类型；协议也需实际确认 |

配置真实模式但缺地址/密钥/协议时返回 AI_NOT_CONFIGURED，不静默变 mock。平台若不支持结构化输出，先取文本再严格 JSON 解析；失败为 AI_OUTPUT_INVALID。

S05 可完成 port、mock、校验及真实适配的明确未配置分支。S12 再以真实接口完成联通。没有 API 示例时，不硬编码 Dify 路由或假设 OpenAI 兼容协议。

## 3. WF01 要求提取

流程：输入检查 → 遍历选定来源块 → 逐批提取 → 跨章节合并 → 返回候选/疑问/来源对账。

模型输出包括类别、适用主体、完整条件、all/any、阶段、证明形式及 source_refs。未提供的跨章节引用列为待确认，不猜。

后端检查：

- quote 是对应来源块的真实摘录，来源属于选定招标文件版本。
- condition_key 唯一、logic 引用完整、未知条件未丢弃。
- 每一批和范围内源块有完成或未解决去向；不能只用 Top-K 检索替代遍历。
- 正式 ID 与 revision 由系统生成；候选待售前确认。

## 4. WF02 材料分类与字段提取

流程：输入来源块 → 分类与材料分段 → 按类别提取 → 返回原文值、规范值、问题。

复用试搭包中的类别和字段定义。主体不能从项目上下文直接填入材料；文件夹名不证明事实。一个文件允许多材料，跨文件材料关联可先人工指定。

后端校验每个非空字段都有当前来源。未知、模糊、冲突分别记录。数值规范化保留单位与原文，长期有效须有明确依据。

顶层 entity_name/person_name 等检索键用于筛选候选；条件判定仍须引用对应有来源的 fact，不单凭检索键就认定主体符合。

## 5. WF03 条件核验

后端先筛选当前候选并执行日期、年度、金额和主体等已支持规则，再调用语义核验。候选筛选应保留可能的错误主体线索，但不得把它当匹配证明。

模型逐条件返回 pass/fail/unknown/not_applicable、证据、问题与补材动作。后端校验 all/any、引用、明确检查的一致性。LLM 给 supported 而硬条件 fail 时不能直接入库为支持，需返回明确不符或 needs_review。

缺材料与解析失败区分；有替代证明路径时逐路径检查。评分材料缺口不自动影响投标决定。

## 6. 当前提示词复用与迁移

[现有 P01—P05 提示词](../group_platform_materials_v1/02_可复制提示词.md) 是起点：P01 对应要求提取，P02/P03 对应分类与字段，P04 对应核验；P05 可用于报告说明，但报告状态和表格由后端固定结果生成。

在 S05 将需要的提示词移植为 `backend/app/ai/prompts/` 中可版本化文件，映射本目录契约；保留原文档。迁移时加入明确输入输出类型与当前允许 ID，不把旧输出结构原样当成已兼容。

提示词和上传文档分别处理，文档中的指令性文本只是业务数据。模型不获得文件删除、改确认或任意数据库写入工具。

## 7. 引用和格式验证

代码验证至少覆盖：类型/枚举、ID 允许集、quote、fact 与材料归属、条件覆盖、源文件版本、材料有效状态、模型输出长度及截止时点。

有结构化输出不等于语义正确，仍需业务反例。没有引用的支持结论不得保存为可确认支持。

原试搭包 `code_nodes_reference.py` 只有部分纯函数，未覆盖完整版本事务和规则归约，不能直接当完整后端。

## 8. 运行与重试

AI 调用落在 job 中；保存请求/响应摘要、provider_run_id、提示词版本、耗时和错误，密钥不进入日志。模型网络重试次数有限，失败原样可见。

相同快照的成功调用可以复用；不跨不同来源版本误用缓存。输出迟到后仍需检查本次快照能否成为当前结果。

mock 接口、真实模型接口、实际 OCR 是三项不同验收。测试 expected_results.json 仅用于验收比较，不喂给真实核验模型。前端和导出均显示实际来源模式。
