# S02 数据、任务与迁移

日期：2026-11-17。状态：verified（SQLite、本阶段数据与任务基础）；S03—S14 未启动。

## 实现范围

- SQLAlchemy Core 关系模型：projects、files、source_blocks、requirements、materials、snapshots、jobs、check_results、review_records、supplement_operations、exports 共 11 张业务表。另有 Alembic 自身版本表。
- 固定迁移 `0001_s02_initial.py`，不在迁移中导入未来可变的模型；提供正反向迁移。含项目索引、任务领取/心跳索引、文件版本唯一约束、要求联合主键、状态约束、项目内复合外键。
- GET/POST `/api/v1/projects`、GET/PATCH `/api/v1/projects/{project_id}`；输入/响应 Pydantic 类型与设计 JSON Schema 对照。
- 项目初始 input_revision=1。PATCH 检查 expected_input_revision；context/scope 完整替换且有变化时递增版本、清空 current_verification_job_id，并将非归档/放弃项目退回 preparing。名称修改不改变业务输入版本。历史任务、结果和人工记录不覆写；后续当前视图需以指针和版本判断失效，S02 不实现结果矩阵。
- Context 校验带时区 deadline 与有效 IANA timezone；deadline 规范为 UTC，deadline_date 由后端时区派生，不接受客户端独立提交。
- `Database.transaction()` 使用 SQLite BEGIN IMMEDIATE 和异常回滚；启用外键与 busy_timeout。幂等哈希基于规范化请求和操作标签。项目创建按全局 key，PATCH 按项目/操作，任务按项目隔离；同键同体返回原始响应，同键异体返回 409。
- 为保持 11 张业务表，项目增加内部创建请求字段和 operation_records_json。`perform_once` 在同一事务内提交数据库副作用和幂等结果；失败回滚，重试不重复已提交副作用。不能包裹 OCR/模型网络调用，后续文件外部副作用仍须按各阶段设计使用稳定操作键与检查点。
- GET `/api/v1/jobs/{job_id}`、POST `/api/v1/jobs/{job_id}/retry`；任务创建为内部 JobStore.enqueue，不开放无约束的任务提交接口。重试只接受 failed/interrupted，创建独立子任务、attempt+1，保留父任务、输入和错误；同一父任务仅允许一个直接重试子任务，继续重试请针对子任务。
- queued→running 原子条件领取；全局串行，5 秒心跳与可持久进度，claim_token 阻止失效领取者提交。过期 300 秒的 running 转 interrupted，不自动重复业务操作。
- 独立进程 `python -m app.tasks.worker`；支持 --once、--recover-only。本阶段没有业务处理器，领取到此类任务明确失败 JOB_HANDLER_UNAVAILABLE，不生成伪解析或核验输出。不会把任务完成直接发布为项目核验结果。
- 建立 Snapshot 类型和持久结构，不创建虚假的业务核验快照或结果。所有业务正式 ID 均由后端 UUID 工具生成。
- 公共领域错误、请求校验错误采用设计 error/request_id 结构，数据库未迁移/不可用返回 503；CORS 允许本阶段 POST/PATCH。
- 更新前端占位文案说明后端接口已提供，不扩展工作台功能。后端启动、迁移、worker 与验收命令已更新。

环境沿用 S01 锁文件：Python 3.11.7、SQLAlchemy 2.1.9、Alembic 1.20.1、FastAPI 0.163.1；未新增第三方依赖。

从 backend 运行（本机 uv=/private/tmp/zb-uv/bin/uv、UV_CACHE_DIR=/private/tmp/zb-uv-cache）：

```sh
uv run --frozen --offline pytest -q
uv run --frozen --offline alembic upgrade head
uv run --frozen --offline alembic current
uv run --frozen --offline alembic check
uv run --frozen --offline python -m app.tasks.worker --once
uv run --frozen --offline python scripts/smoke_s02.py
```

- 后端测试最终 **16 passed**（包含 S01 的 5 项）。覆盖空库迁移与降级再升级、11 表清单、响应 Schema、重建应用后读取、幂等原响应、同键异体、旧 revision 冲突、并发创建和并发 PATCH、重大变更失效且历史确认保留、时区与非法输入。
- 任务测试覆盖并发领取只有一方成功、进度持久、心跳过期恢复、旧 token 的完成与进度写入被拒绝、重试关系/幂等、独立 worker 进程恢复与查询、未实现处理器明确失败。
- 事务测试覆盖文件 logical_file_id/version_no 唯一约束、跨项目复合外键拒绝、事务完整回滚、业务副作用已提交后任务失败再重试仍只执行一次。
- 实际默认库 var/zhb.db 原先仅有 Alembic 版本表；检查后执行 upgrade head 成功，current 为 `0001_s02 (head)`，check 输出 `No new upgrade operations detected.`。
- 独立 worker --once 启动退出成功，无业务任务时不创建假任务。
- HTTP 验收使用独立 var/s02_http_smoke.db 与自动选择的本机空闲端口：创建 201、幂等重放、PATCH 输入版本升至 2、停止并重新启动 API 进程后读取一致，全部通过。测试进程已关闭；默认运行库未写入验收项目。
