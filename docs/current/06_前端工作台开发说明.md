# 前端工作台开发说明

## 1. 页面与路由

| 路由 | 页面及主要行为 |
|---|---|
| /projects | 项目列表、创建、当前状态 |
| /projects/:id/materials | 文件树、上传、解析状态、材料字段和原文预览 |
| /projects/:id/requirements | 要求清单、源文、条件逻辑、修订与确认 |
| /projects/:id/checks | 当前核验矩阵、证据对照、复核和补材 |
| /projects/:id/exports | 导出任务、范围、下载及问题报告 |

项目上下文在公共侧栏或编辑抽屉，任务进度在项目页共享展示。不必单独做管理大屏。

## 2. 材料页

左侧原目录树，显示原名、编号、版本及 parse_state；中间 PDF/图片页面；右侧材料分类、提取字段、原文值与规范值。

上传要求明确 source_kind；可选目录上传保留 relative_path，浏览器不支持时回退多选文件。上传完按任务状态展示，不提前显示解析成功。

支持分页预览、查看原件、定位引用页。坐标不可用时只跳整页并展示摘录，不画猜测高亮。

字段修订需对照原页，填写人工誊写及理由，提交版本检查。成功后使用新材料 ID，保留旧机器值，界面标记人工来源；相关核验需更新。

## 3. 要求页

列表按类别和确认情况过滤；选中后同时显示原文与条件。all/any 以可读“全部满足/任一满足”呈现，必要时显示条件树。

修改提交 expected_revision，服务端创建新版本；冲突时刷新提示。确认只针对当前版本。原文有疑问时保留 pending，不能一键确认清除疑问而不记录意见。

## 4. 核验页

列：要求、业务状态、人工状态、证据材料、问题、建议动作。进入详情看到逐条件结果和对应原文。

始终读取后端当前矩阵和 validity。显示三个不同维度：任务是否结束、条件是否得到支持、是否经过人工复核。

| 情况 | 界面行为 |
|---|---|
| running | 展示进度和已完成量；不可显示全部完成 |
| 解析失败 | 显示失败文件及重试，相关项待确认 |
| contradicted 已复核 | 保留“不支持”标签，另显示“已复核” |
| stale | 显示具体变更原因，禁用当前确认和正式材料包导出 |
| mock | 全局“模拟 AI”标记，报告同样标记 |
| provider 未配置 | 提示配置缺失，不能悄悄展示模拟结果 |

## 5. 补材抽屉

提供新增/替换单选。替换必选当前文件，并展示旧版本；上传新文件后创建 supplement operation。

展示阶段：新文件处理中 → 已提交切换 → 受影响条目重检 → 待复核。区分处理失败与切换后重检失败，后者不能误导用户认为材料仍旧。

接口返回受影响要求时支持查看原因。用户不可通过前端选择“只核对一个”缩小服务器必须处理的影响范围。

## 6. 导出页

工作报告允许有缺口；正式 reviewed_bundle 根据后端 eligibility 判定。显示本次范围、结果数、模拟模式、待解决事项和生成时间。

导出文件名只是副本名，原件内容不改。下载由 API 返回，前端不拼服务器 storage_key。

## 7. 状态与数据

- 业务数据由 API 读取；localStorage 只存界面偏好，不存唯一项目/确认状态。
- API 类型从当前契约维护，禁止为 Demo 再写一套不同枚举。
- 任务轮询有间隔并在完成/失败/离开页后停止；刷新后按 job_id 恢复。
- 请求层统一处理错误结构及 409，功能组件不散落鉴权/密钥逻辑。
- 历史 Demo 中 data.js 和模拟执行不能直接作为生产状态来源。

## 8. 验收

完成真实 API 上传与读取，刷新后结果不丢；打开证据定位正确；补材后显示新版本；409 不误报成功；模拟标记明显；失败项不变成“无材料”。

桌面作为主使用场景，小屏可用基本浏览和复核，不为移动端单独扩展业务模块。
