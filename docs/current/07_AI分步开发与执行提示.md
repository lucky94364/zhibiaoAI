# AI 分步开发与执行提示

本文件供后续开发 AI 按阶段执行。当前仅文档与目录准备完毕，S01—S14 均未实现。不要根据历史 Demo 或 mock 截图推断业务已完成。

## 1. 每次任务的通用提示

把下列模板中的 SXX 替换为目标阶段：

```text
请在当前项目执行 docs/current/07_AI分步开发与执行提示.md 中的 SXX 阶段。

先读取 AGENTS.md、docs/current/README.md、00/01，以及本阶段涉及的数据、接口和验收文档。
检查已有代码和 progress 记录，从实际状态继续，不覆盖用户改动。历史文档只作参考。

完成本阶段必要代码、集成和有意义的验证；不要只输出计划。
使用 frontend/backend 约定目录，复用现有实现。保持当前范围和契约。
如发现文档矛盾，指出具体字段/行为并同步修正文档；不能放宽来源、版本或业务正确性来让测试通过。
真实 API/模型/OCR 缺失时明确记录，完成不依赖它的工作；不要伪造调用或静默用 mock 冒充。
除非我明确指定连续阶段，否则不要扩展到下一阶段。

完成后更新 docs/current/progress/SXX.md 和 development_status.json，写明实现、测试命令及结果、未运行项、外部阻塞和下一步。
最终用简短中文告诉我改了什么、如何验证、还缺什么。
```

常规编码和修复在已授权阶段内自主完成，不把“是否继续修这个错误”变成重复确认。

## S01 工程骨架与配置

读取：00、01、03、contracts。目标文件：frontend 的 Vite/React/TS 工程；backend 的 pyproject、app/main、settings、Alembic 基础；根配置样例与启动说明。

任务：

1. 检查本机 Python/Node，选兼容依赖并锁定，保持包管理器一致（前端 npm，后端 uv）。
2. 实现 GET /health、GET /capabilities；未配置的能力如实 unavailable。
3. 前端建立路由和项目布局骨架，能够读取 health；不填虚假项目数据。
4. 配置加载根 .env，路径相对项目根解析，密钥只留后端。
5. 更新 frontend/backend README 为本机实际可运行命令。

验收：后端启动、前端启动、类型检查和构建；健康接口返回真实模式。此阶段不宣称任务/OCR/AI已完成。

完成提示：记录锁定版本和启动地址，不以只有目录文件算完成。

## S02 数据、任务与迁移

读取：02、03。目标：models、repositories、migrations、tasks。

任务：实现 11 张表及最小索引；项目创建/查询/更新；持久 jobs、claim、进度、interrupted 与重试基础；事务和幂等工具。

项目更新检查 expected_input_revision；重大上下文更新先保守失效。worker 单独进程，首版串行。建立 snapshot 类型但不伪造验证结果。

验收：迁移从空库运行；项目重启后可读；重复 request key 不重复创建；同键异体/旧版本更新冲突；中断任务可见。增加对应事务测试。

## S03 文件上传与持久保存

读取：02、03、04。目标：storage、文件 API、文件登记 service。

任务：单文件 multipart 上传、relative_path、source_kind、不可变原件、指纹、logical/version、列表与下载；普通上传保持 pending，后续成功发布。新旧文件不能靠同名自动替换。

预览入口先返回未就绪明确错误，待 S04 补齐。目录由前端批量调用单文件上传。

验收：PDF/PNG 上传后字节一致；同名文件不覆盖；重复请求不多出版本；路径不能逃逸；服务重启后能下载。

## S04 文档解析、OCR 与来源预览

读取：04、08。目标：parsers、ocr、来源块与页面 API、解析任务。

任务：实现 pdfplumber 提取、页面渲染、真实 OCR 适配与能力检测；混合页补充识别；原文块和位置；Word 转换器检测与受控转换；失败页对账与重试。

工具未安装时报告缺失，先完成其他格式；扫描测试不得通过 fixture 替代。解析重试产生新产物，保留旧证据。

验收：样本文字 PDF、扫描 PDF、PNG 实际读取；图像页返回可辨识文字；页面预览与来源正确；损坏文件/失败页不被忽略。公开 DOC 样本转换未完成时记录该格式尚未验收。

## S05 AI 接口、模拟适配与输出校验

读取：05、contracts、可复用提示词。目标：ai/port、mock、prompts、validators。

任务：三个业务方法；从原提示词迁移适合当前契约的版本；显式 mock；haier_workflow/internal_model 未配置时清晰错误；引用、字段、逻辑键和输出 schema 校验。

mock 的输出来源是显式开发 fixture 或可复现逻辑，不能把 expected_results 当真实模型答案。实际输入没有对应摘录时不得创造 source refs。

验收：正常输出可解析；不存在的 block/fact、错误 quote、格式错误被拦截；真实模式不静默回退；provider/is_simulated 由代码赋值。

## S06 招标要求提取、修订和确认

读取：02、03、05。目标：requirement service、提取 task、修订/确认 API。

任务：范围与来源对账、分批提取和跨章节条件合并；生成要求版本；修订创建新 revision；明确确认绑定当前内容；疑问可见。

不把未确认要求用于正式核验。旧版本和确认记录可追溯，修订不能覆写旧检查引用。

验收：Q01—Q04 提取可复核；all/any保留；旧revision确认冲突；原文引用有效；漏块或未解释引用显示为疑问。

## S07 材料分类与字段提取

读取：02、04、05。目标：material service/task/API。

任务：从真实解析产物调用 WF02；支持单文件多材料；字段、单位、主体和来源；新产物成功后进入当前集合；人工修订记录及相关失效接口。

先覆盖证照、人员、财务关键字段和简单合同，不扩展完整财务分析。

验收：初始三份材料分类合理、字段可回原文；模糊为空/待确认；错主体不会被上下文覆盖；材料提取失败不变成“当前可用”。

## S08 条件核验与结果矩阵

读取：02、03、05、08。目标：rules、verification service/task、checks API、review。

任务：完整输入快照；候选目录检查；日期/金额/主体等规则；all/any归约及替代证据；WF03语义建议；后置校验；生成范围内 result_bindings。

实现人工复核，确认不改变业务状态。GET checks 返回服务端当前矩阵，包括 validity、review_state 及来源。

验收：初始四项结果在成功解析前提下符合标准；硬条件失败不能被模型一句满足覆盖；失败文件不判 missing；旧输入任务迟到不更新当前指针。

## S09 补材、替换与局部重检

读取：02第6—9节、03、08。目标：supplement service、影响分析、幂等提交与重检。

任务：pending 新文件→解析提取→成功后条件提交；区分 add/replace；记录受影响原因；原关联＋新旧类别＋主体＋潜在冲突；重检用全部当前候选；未变结果有依据沿用。

类别不明或上下文变化时保守全量。保留 operation 状态，区分切换前失败和切换后重检失败。

验收：过期证书替换后 Q02 待新复核；新增合同触发原缺失 Q04；旧文件保留；未变文件不重复 OCR；重复请求、并发版本变更及中断不重复切换；沿用记录能回原确认。

## S10 前端完整工作台

读取：06、当前 API。目标：frontend features 和共享组件。

任务：项目列表与上下文；材料树和原文；要求编辑确认；核验矩阵；补材抽屉；任务恢复与错误；模拟模式提示。

所有业务读写接实际 API。参考旧 Demo 的视觉风格，不能沿用其浏览器模拟状态代替后端数据。

验收：真实上传与查询、刷新不丢、409可处理、失败/过期状态可见；来源定位一致；截图和必要浏览器端到端场景检查。

## S11 报告、材料包与用户决定

读取：02第8节、03、06。目标：ExportService、导出任务、下载页、decision API。

任务：report 输出 JSON/CSV 和问题；reviewed_bundle 检查全支持/确认/当前性后打包原件副本、目录与来源；ZIP文件名去冲突；记录模式和范围；显式放弃/归档保存原因。

验收：未确认/stale/失败不导出正式材料包；问题报告仍能导出；ZIP原件字节一致；同名不覆盖；模型不自动放弃。

## S12 真实平台或内部模型联通

读取：05、09。前提：实际接口示例与允许的配置，不需要把密钥写入文档。

任务：先文本→JSON探针，再三个操作映射；请求限制、超时、运行ID、错误和重试；用实际来源输入验证引用。

平台 API 可用优先平台；不可用且内部模型接口可用则直接模型适配，记录真实方式。两者信息都缺时可完成未配置分支与验证脚本，但本阶段状态必须 blocked_external 或 partial。

验收：保留脱敏调用记录，真实 provider 和提示词版本可追溯；不会使用 mock 输出冒充平台结果。

## S13 全链路回归与业务验收

读取：08 全文。目标：关键测试、演示脚本、用时记录。

任务：实际 API/worker/文件跑初始与两次补材；T01—T30按风险覆盖；售前及岗位复核；对比现有方式用时；修正已发现问题。

验收分开记录 mock链路、真实OCR、真实AI、公开DOC样本、业务反例。未完成的真实依赖不允许勾选整体真实闭环。

## S14 部署、运行与交接

任务：部署说明、数据库迁移、持久目录、API/worker/前端启动和停止、依赖版本、配置与故障恢复；如使用 PostgreSQL 运行核心事务用例；整理演示材料。

可按实际部署方式增加容器配置，但先验证文件卷持久、重启恢复及当前模型能力。用户未提供部署主机时交付本地运行文档，不宣称已上线。

验收：其他成员按文档能运行；无密钥入库；备份/恢复和已知限制明确；README与当前实现状态一致。

## 3. 恢复工作与状态

development_status.json 是阶段索引，progress/SXX.md 是证据。发现状态与代码不一致以代码、实际命令及验收记录为准，修正记录，不盲信旧勾选。

每次只跑适合当前改动的检查；新失败或未解决风险才扩大测试，避免无意义重复全量。
