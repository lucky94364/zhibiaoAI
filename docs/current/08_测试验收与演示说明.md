# 测试、验收与演示

## 1. 三层验证

| 层 | 做什么 | 不能代表什么 |
|---|---|---|
| 单元/契约 | 日期、金额、逻辑树、引用、版本、幂等及接口类型 | 不代表 OCR 或模型正确 |
| 组件集成 | 数据库/原件持久、真实解析、真实 OCR、平台或模型调用 | 不代表业务全范围已覆盖 |
| 场景验收 | 上传到补材与导出，用人工答案对照 | 只证明本次样本与反例，不推导总体准确率 |

AI 模拟模式和真实模式分开报告。测试跳过必须记录原因及未覆盖能力，不能算通过。

## 2. 现有输入

复用 `docs/group_platform_materials_v1/samples/manifest.json`；按 stage 上传，首轮不能包含 supplement 文件。

context.json 为模拟上下文；expected_results.json 是人工验收答案，只能由测试对比读取，不作为真实模型输入。

初始 Q01 supported、Q02 contradicted、Q03 supported、Q04 missing；前提是相关文件全部成功处理。OCR 未完成时，受影响项应 needs_review，不能为了对齐答案假设解析已完成。

替换有效负责人证书后 Q02 supported/pending；新增合同后 Q04 supported/pending。原件和初次错误结果保留。

## 3. 必须有的关键测试

| ID | 场景 | 预期 |
|---|---|---|
| T01 | 文件上传后重启 API/worker | 文件与元数据可恢复 |
| T02 | 扫描 PDF 没文字层 | 真实 OCR 或明确 unavailable |
| T03 | 混合 PDF 有扫描页 | 不因首页可提取就跳过附件 |
| T04 | 损坏或不支持文件 | 失败可见，不进入匹配通过 |
| T05 | 主体、人员错误 | 不自动借用其他主体证明 |
| T06 | 有效期结束早于截止日 | fail |
| T07 | 生效日期晚于截止日 | fail |
| T08 | 有效期缺失 | unknown，不能当长期 |
| T09 | 100 万元与 1000000 元 | 单位规范后比较正确 |
| T10 | 单位/币种不清 | unknown，不能猜 |
| T11 | all/any 与替代证据 | 正确处理允许的路径 |
| T12 | 模型不存在的 block/fact ID | 校验拦截 |
| T13 | quote 与原文不符 | 校验拦截 |
| T14 | 相关文件解析失败 | 不能直接 missing |
| T15 | 条件修订后确认旧版本 | 409/过期，旧记录保留 |
| T16 | 新合同补齐旧 missing | 被加入重检 |
| T17 | 新材料可能冲突已通过项 | 已通过项也做影响检查 |
| T18 | 替换解析失败 | 旧有效材料不切换 |
| T19 | 切换后核验失败 | 新版本保留，结果待更新 |
| T20 | 重复同幂等键相同请求 | 返回同资源，无重复版本 |
| T21 | 同键不同请求 | 409 |
| T22 | 旧模型任务晚于补材返回 | 不覆盖当前指针 |
| T23 | 局部重检沿用未变结果 | 有依赖检查及原确认追溯 |
| T24 | 修改负责人/投标主体 | 扩大重检，不沿用不适用证据 |
| T25 | 只缺评分材料 | 不自动决定放弃 |
| T26 | stale 或待复核正式材料包 | 拒绝，工作报告仍可输出问题 |
| T27 | ZIP 文件同名/目录异常 | 不覆盖或逃逸，原件字节保持一致 |
| T28 | 开启真实 provider 但未配置 | 明确失败，不静默 mock |
| T29 | 刷新前端 | 结果来自 API，非 localStorage 唯一副本 |
| T30 | worker 中断后重试 | 可追溯，不重复切换或确认 |

优先实现会阻止错误通过和破坏版本的测试。纯文案/样式不为覆盖率编写镜像测试。

## 4. 阶段完成记录

每个阶段在 progress 下写 SXX.md：范围、文件变更、执行命令与结果、未运行项、真实/模拟状态、外部阻塞及下一步。

最终测试命令由 S01 以后实现并固定，目标约定：

```text
cd backend
uv run pytest
cd frontend
npm run typecheck
npm run build
npm run test:e2e
```

上面是目标命令，本次只有文档目录，没有业务脚本。端到端测试要求实际 API/worker 和样本文件，不伪装静态 HTML 点击为后端闭环。

## 5. 参赛演示

展示顺序：痛点 → 两路处理 → 过期与缺失证据 → 补材重检 → 原文追溯 → 人工确认 → 导出。用公开招标和显式模拟企业资料，不把样本当真实企业能力。

记录售前原有“普通 AI＋人工核对”的用时，与本系统的上传、处理、复核及补材总用时。业务指标：错误支持次数、关键字段错误、来源准确、漏补条目、人工修订量和总耗时。

没有真实平台 API 时可以展示直接模型适配及独立工作流试验，但必须标明实际接入方式。
